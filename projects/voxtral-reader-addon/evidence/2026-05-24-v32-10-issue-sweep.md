# V32 10-Issue Local Audio Sweep

Date: 2026-05-24
Owner: codex-d4e3
Scope: local Voxtral read-aloud install/UX, local `mlx_whisper` transcription install, and P0 buffering/perf clarity.

## Fixed Issues

1. Installer help suggested `--print | plutil -lint -`, which failed locally with stdin/path handling. Fixed by adding a first-class `--lint` mode and replacing the help example.
2. `--no-bootstrap` still performed a health check by default, so a dry validation could fail on a new machine before the service existed. Fixed by making `--no-bootstrap` skip the implicit check unless `--check` is passed.
3. The installer had no way to explicitly request a health check after `--no-bootstrap`. Fixed with a `--check` override.
4. The generated plist interpolated paths and labels without XML escaping. Fixed with shell-side XML escaping before writing dynamic plist values.
5. The new-machine checklist used `install-voxtral-launchagent.sh --no-bootstrap` as verification, which was ambiguous and did not install the LaunchAgent. Fixed to lint first, then run the real install and curl `/health`.
6. The Vidux skill install docs did not show the low-risk lint step. Fixed by documenting `scripts/install-voxtral-launchagent.sh --lint` before install.
7. `scripts/smoke-local-transcription.sh --install` could fail on a stale/broken `mlx_whisper` shim. Fixed by using `uv tool install --force mlx-whisper` for explicit install/repair.
8. The transcription smoke looked stuck during `say`, `ffmpeg`, model load, and CLI transcription. Fixed with `[stage]` logs for dependency checks, audio generation, conversion, duration measurement, model load/transcription, and JSON parsing.
9. The transcription smoke could print `[PASS]` with an empty or useless transcript. Fixed by failing empty transcripts and validating the generated default sample contains the expected local-transcription phrase.
10. Read-aloud generation copy implied all long waits were first-run model loads. Fixed the P0 loading hint to explain that local Voxtral returns one WAV when generation finishes, so warm generation is still visibly "working."
11. Batched read-aloud materialization had a misleading guard that could throw a raw TypeError for an empty batch. Fixed with an explicit `Empty synthesis batch` error.
12. Batched audio splitting accepted empty/tiny decoded audio until later browser operations failed obscurely. Fixed with explicit empty/tiny decoded audio checks before splitting.
13. Browser proof showed the new loading text could still be clipped by the footer's one-line ellipsis. Fixed the player status CSS to wrap long loading messages instead of hiding the "still working" explanation.
