# Voxtral Reader Add-on for vidux-browse

## Purpose

Ship a 🔊 "Read aloud" button in vidux-browse that reads the current artifact / PLAN.md aloud using Mistral's Voxtral 4B TTS on Apple Silicon. The browser UI stays tiny; synthesis runs through a loopback MLX server (`http://127.0.0.1:8765`) using Voxtral MLX weights. Zero cloud, zero Modal, personal use only (Voxtral is CC BY NC 4.0).

The killer use case is hands-free consumption of agent output during walks / commutes — the same goal that drove the abandoned Higgs-on-Modal path (2026-05-01 cycles 1-9). Voxtral is viable locally, but not as a Transformers.js/WebGPU browser model: official support is vLLM-Omni on NVIDIA, while Apple Silicon support comes from MLX ports (`redseaplume/Voxtral-4B-TTS-2603-MLX`, `mlx-audio`).

## Constraints

- ALWAYS: Voxtral runs locally on Apple Silicon through a loopback MLX server (`127.0.0.1:8765`). The browser is only the client/player.
- ALWAYS: No cloud API calls, no Modal, no server-side GPU spend.
- ALWAYS: The browser button fails gracefully when the MLX server is absent and tells the operator which local script to run.
- ALWAYS: Voice playback uses a returned WAV blob and browser `<audio>` playback.
- ALWAYS: Highlight while reading if possible. Current v0 uses approximate word highlighting by mapping `audio.currentTime / audio.duration` across wrapped words because the MLX server does not return word timestamps.
- ALWAYS: Prefer segment-level timing over whole-document timing when possible. The server still does not return word timestamps, so the next accuracy step is rendered-block segmentation + per-segment duration, not pretending we have true alignment.
- ALWAYS: Cache generated WAVs by content hash + model + voice. If text has not changed, replay from cache and skip synthesis.
- ALWAYS: Treat the next reader work as a transcript/player subsystem, not a button polish pass. The bottom player owns playback state; rendered content owns segment/word affordances; the header owns only global browser status.
- ALWAYS: Vanilla JS to match existing vidux-browse stack (Python http.server + plain HTML + marked.js CDN).
- NEVER: Use Voxtral for commercial Leo properties (Snowcubes, Resplit, StrongYes) — license forbids it. Personal scope only (leojkwan, vidux internal tooling).
- NEVER: Claim Voxtral 4B TTS is a Transformers.js/WebGPU browser model. It is a vLLM/MLX model. Prior WebGPU assumption was false.
- NEVER: Bundle the 3.4GB 4-bit weights with vidux-browse — they download once through Hugging Face cache on first real synthesis.
- NEVER: Add an iframe of the HF Space — brittle, cross-origin postMessage isn't documented, and cold-start re-downloads the entire Space shell every click.
- NEVER: Roll our own onnxruntime-web integration — Transformers.js already wraps the decode loop, KV cache, mel-spec preprocessing. ~600 LOC of avoidable work.
