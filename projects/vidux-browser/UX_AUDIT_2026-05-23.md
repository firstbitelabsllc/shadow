## Root cause of Leo's gutter bug — TWO distinct bugs in the same selector family

Both render under `class="plan-row"` so they look like one bug but have different fixes. Both shipped in this audit's first commit.

### Bug A — Artifact rows: meta-line wrap (matches Leo's screenshot)

- **Where:** `static/style.css` — `.plan-row-meta { flex-wrap: wrap }`
- **What:** On narrow sidebars, the `path · age · size` meta line wraps to 2 lines for items with longer paths (e.g. `Snowcubes Switchboard Readiness`), making that row visibly taller. Adjacent rows with shorter paths stay 1-line, so inter-item rhythm breaks.
- **Fix shipped:** `flex-wrap: nowrap` + `min-width: 0` on the meta container, `overflow: hidden; text-overflow: ellipsis; white-space: nowrap` on the path span (the only one that can be truncated — age + size are always short).

### Bug B — Plan rows: parent-vs-leaf progress-row height delta

- **Where:** `static/app.js` (`renderPlanRow` function) + `static/style.css` (`.progress-row` / `.progress-row-with-rollup`)
- **What:** Plans WITH children render `<div class="progress-row progress-row-with-rollup">` with two `.progress-row-line` children (gap: 6px). Plans WITHOUT children render `<div class="progress-row">` with the bar+label directly (no `.progress-row-line` wrapper, gap: 4px). Height delta ~24px per row.
- **Fix shipped:** Unified the render in `app.js` — always wrap in a `.progress-row-line`, even for leaf plans (single line). The rollup line is conditional; the wrapper + first `.progress-row-line` is invariant.

### Bug C — Dark-mode hover

- **Where:** `static/style.css` — default `.plan-row:hover { background: var(--paper) }`
- **What:** In dark mode, `--paper` IS the base background, so the hover produced zero visible feedback.
- **Fix shipped:** Added `.plan-row:hover { background: var(--paper-2) }` inside the dark-mode `@media` block.

## Findings by audit stream

### 1. Visual + UX polish (Agent 1)

10 issues. Top 3 by visible impact (beyond Bug A/B/C above, all of which shipped):

| # | File | Issue | Proposed fix |
|---|---|---|---|
| 1 | `style.css` `.plan-row.is-child` | indent `calc(6px + var(--child-depth) * 18px)` — depth ≥3 causes horizontal scroll on 360px sidebar | Clamp depth or reduce multiplier to 12px |

### 2. Accessibility — WCAG 2.2 AA (Agent 2)

**6 CRITICAL blockers for open-source release:**

1. **No keyboard nav on sidebar list** — items not focusable. Add `tabindex="0"` + arrow-key handler + Enter/Space activation. WCAG 2.1.1 Level A.
2. **Annotation popover has no focus trap + no Escape handler** — focus escapes to background. Implement trap + ESC close. WCAG 2.1.2 Level A.
3. **Form inputs in popover lack `aria-label`** — screen readers can't announce purpose. Add labels for author + body. WCAG 1.3.1 Level A.
4. **No `aria-live` region for read-aloud chunk highlight** — audio-only feedback insufficient. Add hidden `aria-live="polite"` region. WCAG 4.1.3 Level AA.
5. **No `prefers-reduced-motion` support** anywhere. Wrap transitions in `@media (prefers-reduced-motion: no-preference)`. WCAG 2.3.3.
6. **No skip-to-content link** in index.html. Add `<a href="#pane" class="skip-link">` shown on focus. WCAG 2.4.1 Level A.

Important (pre-release): `:focus-visible` coverage gaps, descriptive labels on comment-target buttons.

### 3. Mobile / responsive — iPhone + iPad on LAN (Agent 3)

**Showstoppers on iPhone portrait (390px):**
- Topbar cramped — 7 controls in ~390px width. Voice select truncates.
- Read-aloud section-play buttons reveal hover-only (`opacity: 0` default) — invisible on touch.
- Annotation popover sized 366px on 390px viewport → only 12px side margins.

**Showstoppers on iPad portrait (768px):**
- Sidebar fixed at 360px = 47% of viewport. No iPad breakpoint to revert to comfortable side-by-side.

**Tap-target violations** (<44pt):
- `.sidebar-toggle`
- `.comment-anchor button`
- `.root-readaloud-voice` (and similar dense topbar controls)

### 4. Theme + dark mode (Agent 4)

**16 tokens** defined in `:root` (paper/ink/rule/hot/cold/stale/accent/task-* etc) — sound foundation. Dark mode override works.

**Gaps:**
- **No user-toggleable theme switch** — only OS `prefers-color-scheme`. Blocks contributor testing.
- **Error component fully hardcoded** (background + text in both modes). Outside token system.
- **Box-shadow opacity literals** — should use `--shadow-opacity` token.

Recommendation: add `--error-*`, `--warning-*`, `--shadow-opacity-*` tokens + UI theme toggle + `THEMING.md` for contributors + Stylelint rule rejecting hex literals outside `:root`.

### 5. Test infrastructure plan (Agent 5)

**Stack:** Vitest + happy-dom (unit) + Playwright (e2e) + extend existing pytest (server).

**Layout proposed:**
```
browser/tests/
  unit/{format,plans,url-state}.test.mjs    # Vitest, pure helpers
  e2e/{smoke,annotate,comments,readaloud,visual}.spec.ts  # Playwright
  fixtures/fake-dev-root/ + sample-comments.jsonl
tests/test_browser_endpoints.py             # pytest, contract tests
playwright.config.ts + vitest.config.mjs    # NEW configs
.github/workflows/test.yml                  # add browser-e2e job
```

**Prerequisite refactor (~15 lines):** `server.py` needs `--root`, `--port`, `--comments-path` argparse flags so Playwright `webServer` can boot it hermetically against fixtures. Without this, e2e scans contributor's real `~/Development/`.

**Visual snapshots:** Linux-only (font rendering diverges from macOS), `maxDiffPixelRatio: 0.02` to tolerate hinting drift, 3 viewports (390/768/1440).

**Day-1 contributor commands:** `npm install && npm run playwright:install && npm test`. Splits into `npm run test:js / test:py / test:e2e`.

### 6. Open-source readiness (Agent 6)

**3 BLOCKERS:**
1. **`LEGACY_REPO_ALIASES`** in `server.py:54` maps `"mobiledevcombine-web" → "strongyes-web"` — leaks Leo's internal repo naming. Make configurable via `VIDUX_REPO_ALIASES` env JSON OR remove.
2. **Undocumented `mlx-audio.server` dependency** (`index.html:18-28`) — readaloud buttons assume port 8000 service. Document as optional + add graceful UI fallback.
3. **Conflicted README** — claims "generic" but examples assume `~/Development/` + macOS + port 7191 with no context.

**Should-fix:** "Leo's fleet" references in `server.py`, undocumented `readaloud.js` purpose, Phase 5 of existing PLAN.md mixes Snowcubes/Nicole/Moussey extensions into generic doc.

**Repo split recommendation:**
- Keep in `vidux-browse` (core): server.py minus aliases, app.js, index.html, receipts.html, generic CSS
- Move to `vidux-browser-extensions` (Leo-only): Moussey :4321 redirects, Snowcubes artifact handlers, Nicole cards, mlx-audio.server integration

**Missing files:** LICENSE, CHANGELOG.md, CONTRIBUTING.md.

## Decision log

- **Why 6 agents, not 20:** parallel research is high-leverage but redundant agents return diminishing returns. 6 cleanly partitioned surfaces (visual / a11y / mobile / theme / tests / OSS) cover the request without overlapping work.
- **Why ship gutter fix first:** Leo's verbatim stated bug. Highest signal-to-effort. CSS+JS change scoped to <30 lines.
- **Why NOT do P1-P3 this session:** structural depth + needs Leo's call on naming/repo split. Cap of 2 parity-clean PRs/week per `/pilot-leo` discipline. Logging as ranked execution plan.
- **Why Vitest+Playwright over Jest+Cypress:** ESM-native, no Babel, cross-browser, ships own runner, smaller dependency surface for OSS contributors. Per Agent 5.
