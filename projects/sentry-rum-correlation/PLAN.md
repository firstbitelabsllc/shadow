# Sentry RUM Correlation (Resplit iOS)

## Purpose

Datadog-RUM-style passive correlation between ASC TestFlight tickets and Sentry events using IDFV + scan_id + a dynamic surface tag. **No new in-app feedback widget** — Apple TestFlight's native shake-to-feedback remains the user-side surface; we only augment debugging context. The cron-side bridge enriches ASC plan rows in `.cursor/plans/app-store-feedback.plan.md` with matching Sentry event context (install_id, recent breadcrumbs, last surface, last scan_id) so a triaging agent at debug-time can stop guessing which scan / which user / which device produced the report. Three IDs travel with every Sentry event: `install_id` (IDFV — per-vendor stable, FBL only), `session_id` (Sentry auto-session, already on), `scan_id` (UUID minted at OCR start, propagated through 5 pipeline checkpoints). One dynamic tag: `surface` (set by SwiftUI modifier `.sentrySurface(_:)` on the active screen). Core logic extracted into `SentryCorrelationService` (Factory DI) so views never call SentrySDK directly and tests can swap in a fake.

## Constraints

- **ALWAYS** — Factory DI for `SentryCorrelationService` per `Container+Database.swift` convention; `Container.shared.callAsFunction` registration, protocol-typed property, fake substitutable in tests
- **ALWAYS** — core logic in `SentryCorrelationService` (or `BreadcrumbContextManager` if we split scan-trail bookkeeping); zero `SentrySDK.*` calls in views or view models
- **ALWAYS** — scrub PII per Lane B privacy audit: `install_id` is per-vendor IDFV (Apple-sanctioned, GDPR-acceptable), merchant names get SHA-256 hashed before tagging, never ship photo bytes in breadcrumbs (Sentry's `attachScreenshot` already redacts via the SDK's screenshot processor)
- **ALWAYS** — MT-5 regression test bundled in the same PR as each behavior change (per resplit-ios CLAUDE.md §Regression tests on revert-prone surfaces)
- **ALWAYS** — visual proof on the cron-bridge end-to-end: screenshot of an enriched ASC plan row showing the linked Sentry event URL + last surface + scan_id (per resplit-ios CLAUDE.md §Visual Proof Merge Gate)
- **ALWAYS** — every breadcrumb payload < 413 bytes; CI guard via unit test that asserts `JSONEncoder().encode(breadcrumb).count < 413`
- **NEVER** — Sentry User Feedback Widget (Apple TestFlight shake is the user-side surface; Leo explicit no)
- **NEVER** — bookkeeping-only PRs (per resplit-ios CLAUDE.md MT-1) — every PR ships code AND tests AND, where user-visible, visual proof
- **NEVER** — log raw merchant names, raw OCR text, raw amounts, or raw participant names in breadcrumbs/tags (PII)
- **NEVER** — ship a breadcrumb whose `data` field exceeds Sentry's soft limit (would silently truncate)
- **NEVER** — write to `SentrySDK.startSession()` / `SentrySDK.endSession()` manually; the auto-session tracking already manages this and manual calls would double-count

## Decision Log

- [DIRECTION] 2026-05-09 — Drop Sentry User Feedback Widget per Leo "we dont want sentry widget"; keep TestFlight native shake-to-feedback as user-side surface. We only do passive observability that augments debugging.
- [DIRECTION] 2026-05-09 — Use IDFV (`UIDevice.current.identifierForVendor`) as `install_id` join key. Per-vendor (FBL) stable across reinstalls *within vendor scope*; resets on full uninstall but the join window is short (TestFlight feedback typically arrives within hours of repro). Apple-sanctioned, GDPR-acceptable, no consent gate required. Alternative considered: minted UUID stored in Keychain — rejected because it survives full uninstall (longer privacy tail) AND because the IDFV is already computed at `LiveSessionViewModel.swift:291` (zero new code on the read path).
- [DIRECTION] 2026-05-09 — `SentryCorrelationService` extracted, Factory DI per `Container+Database.swift` convention (Leo explicit ask). Service is protocol-typed (`SentryCorrelationServiceProtocol`) so tests can substitute `FakeSentryCorrelationService`. Concrete impl is `internal`, never imported by view modules.
- [DIRECTION] 2026-05-09 — Cron-side enrichment extends existing `scripts/asc_beta_feedback.rb` with a new `--enrich-sentry` mode rather than introducing a new infrastructure service. Pairs with the existing `resplit-watch` 30-min launchd cron (no new daemon).
- [DIRECTION] 2026-05-09 — `surface` tag is overwritten on each screen mount (`onAppear`), not appended. Sentry's tag model is single-value-per-key, so "append" would just be the latest write anyway; explicit overwrite makes the intent obvious in the service API.
- [DIRECTION] 2026-05-09 — Scan checkpoints use `SentrySDK.addBreadcrumb(...)` not custom events. Breadcrumbs travel with the next error/crash event automatically; custom events would create cardinality explosion in the Sentry UI for what's debugging context, not metrics.
- [DIRECTION] 2026-05-09 — Cross-references to lane investigation files are pre-declared in Tasks above so future agents working any of the 4 lanes (A/B/C/D) know where to land their findings without re-deriving the file naming convention.
