# ObservabilityBus — vendor-agnostic event stream (Resplit iOS)

## Purpose

Vendor-agnostic, future-proof event stream for Resplit iOS. Every screen emits a small, JSON-shaped `ObservabilityEvent` (present / action / error) carrying three IDs (install / session / scan) and minimal scrubbed metadata. A single `ObservabilityBus` fans events out to N pluggable `ObservabilityEventSink` adapters — Sentry, PostHog, console, and any future vendor (Datadog, custom backend, RUM tool we haven't picked yet) — without view code ever knowing which vendors are wired. This collapses the prior `SentryCorrelationService` design into a single `SentryEventSink` adapter and unifies the analytics + error pipelines so PostHog and Sentry share one identity space (`install_id`). The cron-side ASC enricher continues to write Sentry permalinks into `.cursor/plans/app-store-feedback.plan.md` rows but reads from whichever sink can answer the device-id + time-window query (Sentry first, PostHog as fallback). No raw event payloads ever land in git — only permalinks survive.

## Constraints

- **ALWAYS** — Factory DI for `ObservabilityBus` and every sink per `Container+Database.swift` convention; `Container.shared.callAsFunction` registration, protocol-typed properties, fakes substitutable in tests
- **ALWAYS** — every event flows through `EventScrubber` BEFORE reaching any sink (defense in depth — vendor sinks stay dumb, can't accidentally leak PII even if a future vendor SDK does something unexpected)
- **ALWAYS** — sinks are pure functions of `ObservabilityEvent` (no other inputs, no global lookups, no I/O on the emit path beyond what the wrapped vendor SDK does) — makes testing trivial and per-sink failures isolated
- **ALWAYS** — bus emits even if a sink throws — per-sink failures are caught and logged to the `ConsoleEventSink` (DEBUG) or swallowed (RELEASE); never break the user-facing call site
- **ALWAYS** — MT-5 regression test bundled in same PR per resplit-ios CLAUDE.md §Regression tests on revert-prone surfaces
- **ALWAYS** — visual proof on cron-bridge end-to-end: screenshot of an enriched ASC plan row showing the linked Sentry permalink + last surface + scan_id (per resplit-ios CLAUDE.md §Visual Proof Merge Gate)
- **ALWAYS** — every emitted event payload (post-scrub) < 413 bytes; CI guard via unit test that asserts `JSONEncoder().encode(event).count < 413`
- **NEVER** — reference vendor-specific types (`SentrySDK`, `PostHog.shared`, etc.) in any view code, view model, or domain manager — only sinks know about vendors. Any `import Sentry` or `import PostHog` outside `ResplitCore/Observability/Sinks/*.swift` is a bug.
- **NEVER** — write breadcrumb / event payloads into git-tracked files (Lane B retention rule — only Sentry/PostHog permalinks survive in `.cursor/plans/app-store-feedback.plan.md`)
- **NEVER** — Sentry User Feedback Widget (Leo explicit no; TestFlight shake stays user-side)
- **NEVER** — bookkeeping-only PRs (per resplit-ios CLAUDE.md MT-1) — every PR ships code AND tests AND, where user-visible, visual proof
- **NEVER** — log raw merchant names, raw OCR text, raw amounts (use bucketed: `"<10"`, `"10-50"`, `"50-200"`, `">200"`), or raw participant names; all of these are explicit EventScrubber rules
- **NEVER** — write to `SentrySDK.startSession()` / `SentrySDK.endSession()` manually; auto-session tracking owns this; manual calls would double-count
