# Verb refusals — cause to fix

One row per refusal surface observed on this machine's shadow build. The
refusal text is the search key; the fix is the working invocation.

| Refusal (verbatim or near) | Cause | Fix |
| --- | --- | --- |
| `stale adoption must preserve access and write scope` | adopt-expired flags do not reproduce the stored claim | read `claims[]` in `~/.shadow/board.json`; re-throw with `--access`, `--path` (once per stored write_scope entry), and `--repo` as stored |
| `the completed plan would fail shadow lint (DOD-EARLY ...)` | accepting a milestone DoD row while sibling rows are pending | drain the sibling rows first; refusal names the row, not the blockers |
| `~X is read-classed — record the observation as a passing PROOF line ... then accept` | observation not recorded as a canonical passing PROOF receipt, or recorded with `pass` at the head instead of the result tail | amend `--observation '<observed> -> pass: <details>'` (arrow REQUIRED, result must START with `pass`), then throw, then accept. `accept` re-checks the recorded receipt, not the live conversation |
| `shadow plan reopen: ~X is [completed]; reopen opens blocked rows only` | trying to reopen a row completed on a HOLD verdict | route the follow-up through a live pending row covering the work, or park with an exact wake |
| `shadow throw: claim refused: ~X is [completed], not claimable` | same — completed rows have no throw path | same as above |
| `plan amend: ~X is claimed by <other seat>, not <you>` | amending before owning the claim | throw/adopt first, then amend (order matters, not documented in --help) |
| `the completed plan would fail shadow lint (PROOF-ARGV0 ...)` naming a sibling row | machine-local amend lints the whole plan; a sibling's cmd proof blocks it | pass `--repo <checkout where the sibling's script resolves>` per the plan's own addendum |
| `PROOF-SHELL-OPERATOR ... is passed as a literal argument` | shell metacharacters (`;`, `()`, `>`) inside a proof/note string | wrap the command, keep notes pointer-style plain words |
| `~X carries a cmd proof; run shadow accept to rerun it` | `--observation` on a cmd-proof row | cmd rows have no note channel; notes ride inside the proof string |
| `the computer board's entity-plan pointer is unusable ... machine-local --entity accept also requires --repo` | machine-local accept without a proof source checkout | add `--repo <source checkout>` even for read-class rows |
| `--entity with --repo requires a machine-local entity` | combining entity id with repo for a committed product-repo entity | throw repo-first: `shadow throw --repo <checkout> ...` (no `--entity`) |
| `no task carries ~X in the stored canonical entity plan` (repo-first) | the checkout's plan generation predates the row, or the row was re-scoped upstream | refresh origin/main in a clean detached worktree and throw from there; if the row moved upstream, the claim is a dead end — document, don't force |
| `plan amend: amend edits machine-local plans only; a committed product plan is edited in a branch` | trying to park a committed product-repo row via plan amend | record the wake through the repo's own review flow; adopt-then-return if the wake is already in the plan |
| `return: claim is owned by <other seat>` | return after a failed adopt | the stale claim still stands; only its owner or a board owner can move it |
| `shadow: unknown command: amend` | `plan amend` is not a top-level verb | run it as `shadow plan amend --entity <id> --row '~X' --by <seat> --observation '... -> pass: <details>'` |
| `the following arguments are required: --entity, --row, --by` | positional `~id` (or omitted flags) on `shadow plan amend` | same invocation as the row above — throw's `--task` is not an amend selector |
| `shadow return: the following arguments are required: --row` | return takes `--row`, not throw's `--task` | `shadow return --entity <id> --row '~X' --by <seat>` |
| `shadow init: current directory is not inside a Git worktree` | entity mint needs a repo | `git init` an empty carrier repo first, commit once, then `shadow init --here`; the plan lands at `~/.shadow/plans/<name>/PLAN.md` with template rows `~a1b2`/`~b2c3` |
| `shadow throw: claim refused: no task carries ~X in the stored canonical entity plan` | entity id points at a different plan than the row lives in — sibling entities share name stems | read `shadow status --json` `v4_plans[]` and match `entity_name` to `next_unclaimed` before throwing; never pick an id by name prefix |
| `HOT-PLAN-BYTES` while reopening a machine-local incident row | retained plan content exceeds the shared hot-plan budget | target the canonical plan directory with `shadow lifecycle --repo <plan-directory> --by <seat> --json`; inspect archive eligibility and predicted bytes before applying anything. `--self-compact` may save too little, so inspect its result rather than treating exit zero as recovery. If a size change is explicitly authorized, locate the installed `HOT_PLAN_MAX_BYTES` owner, make the bounded change, test acceptance at the ceiling and refusal above it, then reopen and claim the incident row. Do not raise row or milestone limits as a side effect. |
| `self-compact edits machine-local plans only` when the plan is machine-local | the product checkout was passed instead of the canonical plan directory | resolve the board's plan path and use its parent directory as lifecycle `--repo`; retain the product checkout separately for proof-source commands |
| `--access write requires --path; paths require --access write` | `--path` added to a throw without write access | write claims carry `--path` (one per stored write_scope entry); read/unscoped claims throw with `--access` only, no `--path` |
| `~X is not claimed; run shadow throw before accepting it` | accept on a row this seat does not hold — typically a DoD row whose dependency just completed | throw the row, then accept; skip throw only when a wake says the passing observation is already recorded |
| `PlanStoreError: plan root changed before exact restore` | `restore_exact_root` given the known-good root digest as `expected_current_root` | `expected_current_root` is the digest of the bytes actually on disk now (the corrupt fence); `target_root_bytes` is the good root |
| `referenced object is missing: expected digest <d> at .../PLAN.d/...` right after minting a tree in a test | objects written under `.PLAN.d` (leading dot) | the store reads `PLAN.d/objects/sha256/<d[:2]>/<d>` — mirror the real plan layout exactly |
| `--observation must read '<what was observed> -> <result>'` | observation string missing the `->` separator entirely | include the arrow: `'<observed> -> <result>'`; both amend and the accept receipt parser require it |
| accept keeps refusing "record the observation" even after an amend that looks passing | result tail does not START with `pass` (e.g. `-> proof shadow#123 4 passed`) — the checker tests `result.startswith('pass')` on the canonical receipt's result group | re-amend with `-> pass: ...` as the literal tail; mid-string `->` inside the observed half does not satisfy the parser |
| `shadow throw: claim refused: ~X still needs ~Y` right after Y's observation was recorded | Y is read-classed and recorded but not FLIPPED — the `needs:` gate clears on accept (state flip), not on a recorded observation | complete Y's accept (throw + accept with the passing receipt in place), then throw X |
